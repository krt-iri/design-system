Lagereintrag — Menge getrennt je Auftrag & Einsatz aufteilen

Je Eintrag wird die Gesamtmenge (z. B. 2.480 SCU) aufgeteilt — getrennt nach Aufträgen und nach Einsätzen. Beide Aufteilungen sind unabhängig; jede wird gegen die Gesamtmenge abgeglichen (Verteilt / Rest). Aufträge = orange, Einsätze = blau. Offen ist nur noch die Platzierung — unten drei bedienbare Optionen.

Festgelegt

Modell G — getrennte Mengen. Die Menge wird zweimal unabhängig erfasst: einmal über die Aufträge, einmal über die Einsätze (jede Summe soll die Gesamtmenge treffen). Es gibt keine gekoppelte „Position“ aus Auftrag+Einsatz. Jede Zuordnung trägt ein eigenes Mengenfeld.

A Ausklappzeile · zwei getrennte Aufteilungen

Inline-Ausklappzeile (kein Overlay)

Ein kompakter Button je Eintrag klappt unter der Zeile ein Panel auf mit zwei nebeneinanderliegenden Aufteilungen: links Aufträge, rechts Einsätze — je Liste Zeilen aus Zuordnung + Menge, „+“ und ein eigener Verteilt/Rest-Abgleich. Bleibt im Tabellenfluss; mehrere Einträge lassen sich gleichzeitig öffnen.

Vorteile
  • Kein Overlay — bleibt im Tabellenfluss; mehrere Einträge gleichzeitig offen.
  • Beide Aufteilungen nebeneinander sichtbar, jede mit eigenem Rest-Abgleich.
  • Sofort wirksam; Zeile bleibt geschlossen schmal (ein Button).
Nachteile
  • Offene Panels erhöhen die Höhe (wie Notizen); viele offen = lange Tabelle.
  • Zwei Listen brauchen etwas Breite — auf sehr schmalen Screens untereinander.
B Modal · zwei getrennte Aufteilungen

Verwaltung im Modal

Derselbe Button öffnet ein Modal mit den zwei getrennten Aufteilungen. Maximaler Platz, „Speichern“/„Abbrechen“, gesperrt bei Über-Verteilung. Die Eintrags-Zeile bleibt unter allen Umständen minimal.

Chips mit Menge, direkt im Eintrag

Die leichteste Variante: je Gruppe (Auftrag/Einsatz) stehen die Zuordnungen als Chips mit Menge („#1042 · 1.000“) direkt in der Zeile; Klick auf einen Chip öffnet einen Mini-Editor (Menge / entfernen), „+ Zuordnen“ fügt hinzu. Ein kleiner Rest-Chip je Gruppe zeigt den Abgleich. Gut für einfache Fälle.

Entscheidung & Umsetzung

Festgelegt: Variante C — Inline-Chips mit Menge. Je Gruppe (Auftrag/Einsatz) stehen die Zuordnungen als Chips mit Menge direkt im Eintrag; Klick auf einen Chip öffnet den Mengen-Editor, „+ Zuordnen“ fügt hinzu, ein Rest-Chip je Gruppe zeigt den Abgleich. Auf beiden Seiten (/inventory/my, /inventory/all) und im Einbuchen-Formular.

Abgleich-Regel: unverteilter Rest ist erlaubt (Rest > 0 = neutral „… frei“, Rest 0 = grün); nur Über-Verteilung (Rest < 0) ist unzulässig. Mengen werden getrennt je Auftrag und je Einsatz erfasst (Modell G).

Umsetzung (Design-System-Repo → Submodul im Basetool → Produkt): inventory-entry-multi-assign-claude-code-auftrag.md. Kanonische Klassen: .assoc-split, .assoc-chip(--order/--mission) + .assoc-chip__amt, .assoc-add(-wrap), .assoc-pop.

Gilt für /inventory/my, /inventory/all und das Einbuchen-Formular.
Datenmodell (Modell G): zwei getrennte Zuordnungstabellen je Eintrag — { jobOrderId, amount } und { missionId, amount }; je Tabelle Σ amount ≤ Gesamtmenge. Abgleich: Rest = Gesamtmenge − Σ; unverteilter Rest erlaubt, nur Über-Verteilung (Rest < 0) unzulässig.
Bedienbares Mock — Hinweis: Werte in <select>/Zahlenfeldern erscheinen in DOM-Screenshots leer, sind im echten Browser aber gesetzt. Systemklassen .tree-*, .chip*, .krt-modal*, .krt-combobox*, .btn*; Mengenfelder sind ein neues, noch nicht ins System übernommenes Muster.
